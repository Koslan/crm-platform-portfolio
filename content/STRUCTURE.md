# Как устроен проект сейчас

Снимок на 30 августа 2026. Пересобрать актуальную версию: `npm run build && node content/_export.mjs`.

## Что это за сайт

Портфолио CRM-инженера. Ключевая идея: не рассказывать про виджеты Zoho, а **запустить их вне CRM** —
против эмулятора платформы в браузере, на сгенерированном датасете, с переключателем отказов.
Ни бэкенда, ни сети: всё собирается в один HTML-файл, который и есть сайт.

## Сборка

```
src/app.html          оболочка: CSS, роутер, ВСЕ реестры страниц и текстов   (2 505 стр., CRLF)
src/*.js         ×10  модули демо (event-page, board, teams, pages, diagrams, …)
platform/*.js    ×2   эмуляторы Zoho и Salesforce (COQL, ZOHO.CRM.API, режим отказов)
data/generate.mjs     сид-генератор датасета с намеренными дефектами
        ↓ build.mjs (склейка + инлайн dataset.slim.json)
dist/index.html       полный документ для GitHub Pages
dist/artifact.html    тот же контент фрагментом
```

Проверки: `npm test` — 240 headless-проверок Playwright в девяти `smoke*.mjs`, падают на любой
console error. CI (`.github/workflows/deploy.yml`) прогоняет три гейта: целостность датасета →
скан на утёкшие идентификаторы и креды → тесты.

## Роутер и реестры

Всё, что определяет страницу, лежит в `src/app.html`:

| Реестр | Что задаёт |
| --- | --- |
| `TABS` | пять вкладок: About me, Zoho, AI, Salesforce, Full-stack |
| `ZOHO_GROUPS`, `AI_ITEMS`, `SF_ITEMS`, `FS_ITEMS` | пункты навигации: `id`, заголовок `t`, подпись `s`, вид `kind` |
| `ALL` | плоская карта id → пункт, собирается из массивов выше |
| `PAGE` | страницы со своим рендерером |
| `REC` | страницы-записи через общий шаблон `viewRecord()` |
| `CASES` | лонгриды, рендерит `vCase()` |
| `PAIR` | write-up → живое демо (callout «See it live») |
| `STORY`, `TIPS`, `EDGES` | карта навыков, подсказки и схема интеграций на About |
| `REC2ITEM`, `DEMO2ITEM`, `FIXED` | старые маршруты, которые обязаны продолжать резолвиться |

**Правило приоритета** (`vItem`): `PAGE` → `CASES` → заглушка. Если id есть и там и там,
запись в `CASES` не рендерится вообще. Сейчас так с двумя: `agent-journal` и `sf-sync` —
их тексты в `CASES` мёртвые, это помечено в соответствующих md.

Чтобы `#/p/<id>` вообще открылся, id должен быть в одном из массивов навигации — `PAGE`
или `CASES` сами по себе маршрут не создают.

## Пять архетипов страниц

1. **Таб-индекс** (5) — `vAbout / vZoho / vAI / vSF / vFS`. Лид + сетка карточек.
2. **Живое демо со своим рендерером** — `PAGE`: `event`, `orghealth`, `sf-lwc`, `agent-journal`.
   Проза вплетена в разметку рендерера.
3. **Живое демо через общий шаблон** — `REC` + `viewRecord()`: `solution`, `board`, `chat-recap`,
   `chat-tracker`. Жёсткая структура: `sub` → «The record» → «What to try» → [диаграмма] →
   «Why it was not straightforward». Менять порядок нельзя, не трогая шаблон.
4. **Лонгрид** — `CASES` + `vCase()`. Свободный массив `body` из пар «заголовок → абзац»,
   опциональные `role` и диаграммы, вставляемые по индексу `at`.
5. **About** — особая: блоки в `vAbout()` + `STORY` (76) + `TIPS` (78) + терминал + SVG-карта `EDGES`.

## Диаграммы

Движок — `src/diagrams.js`, `window.Diagrams.render(spec)`. Диаграмма описывается **данными**,
не координатами. Три архетипа в работе:

- `chain` — цепочка шагов с чекпойнтами, отказами и связями (`rails`): `chat-recap`, `chat-tracker`
- `authority` — матрица владения полями: `cross-system`, `org-tooling`
- `funnel` — вход → правила → гейты → корзины: `cross-system`

Вставка в лонгрид — по индексу `at` (после какой секции `body`). Страница может нести несколько
диаграмм: `dgs: [...]`, вставка идёт с конца, чтобы ранняя не сдвигала индекс поздней.
Движок сам подхватывает любую `.dg` через `MutationObserver` на `#view` — вешать обработчики руками не нужно.

Половина всего текста — на одной странице About. Живые демо, ради которых сайт существует,
несут меньше всего: ~240 слов на страницу. Самый большой лонгрид — `cross-system` (1 915 слов),
в 2,3 раза больше следующего.

## Тон текстов

Наблюдаемый по всему сайту, стоит держать при правках:

- Каждая страница отвечает на три вопроса: **что мешало → что построено → чем за это заплачено.**
  Третий не опускается: «The trade», «Why it was not straightforward», «The risk that remains».
- Ограничение называется до решения. Не «построил ретраи», а «события не переприсылаются,
  отклонённая запись — потерянное событие».
- Числа конкретные и проверяемые (17 почтовых ящиков, 160 КБ за 0,88 с, порог 40 и 60).
- Про то, чего система не умеет, говорится прямо, а не сглаживается.
- Никаких имён работодателей в описаниях систем, никаких реальных идентификаторов — за этим
  следит CI-скан.
